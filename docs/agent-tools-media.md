# Инструменты агента и анализ медиа

## Пользовательский тулсет

В настройках инструментов мастер «Настраивать инструменты» включает пользовательский список отключений. По умолчанию мастер выключен, список отключений пуст: используется штатный набор инструментов. Выключение мастера не удаляет сохранённый выбор. Новые дополнительные инструменты разрешены по умолчанию.

Настройки только уменьшают штатный набор. Режим Ask/планирование, персона, разрешение управления браузером, режим генерации изображений и существующие переключатели MCP/плагинов продолжают действовать. Основные инструменты защищены от отключения. Изменение списка применяется к следующему запуску агента; активный запуск использует свой согласованный набор.

## Каталог и фильтры

`models.dev` содержит `modalities.input` и `modalities.output`. Они сохраняются отдельно; вход видео не считается автоматически поддержкой изображений, вход аудио отличается от выхода аудио. Для совместимости сохраняются STT/TTS-теги старых моделей.

Доступны назначения моделей анализа видео и аудио как fallback. Основная модель чата (включая per-chat override) используется первой, когда провайдер/модель поддерживают подтверждённый transport. Capability-тег означает возможность модели по каталогу, **не гарантирует поддержку передачи медиа провайдером**. Старая версия кэша без модальностей использует старые теги до обновления каталога.

## Инструменты

- `analyze_video(path, question?)`: анализ локального видео сначала текущей моделью чата (для субагента — его моделью), если её провайдер имеет подтверждённый нативный media transport; иначе назначенной модели `video`.
- `analyze_audio(path, question?, task?)`: анализ либо расшифровка сначала текущей модели чата (для субагента — его модели) при поддерживаемом transport; иначе назначенной модели `audio`.

Инструменты возвращают текст отдельного вызова анализа: медиа отправляется выбранной поддерживаемой модели inline, но не добавляется в контекст основного чата как нативное вложение. Вложения дают агенту локальный путь; загрузка выполняется только при вызове инструмента.

### Поддерживаемые транспорты

- Официальный Google Gemini API: нативный `generateContent` и inline-медиа.
- Официальный OpenAI API: поддерживаемые аудиомодели chat completions, вход WAV/MP3, выход текст.
- Неизвестные прокси, Syntee Gateway и остальные форматы API не считаются совместимыми автоматически. Инструмент возвращает понятную ошибку без загрузки файла.

### Ограничения первой версии

- Максимальный локальный файл — 14 MiB, чтобы inline-base64 вместе с JSON укладывался в консервативный лимит запроса Gemini.
- Видео: MP4, MOV, WebM, MPEG.
- Аудио Gemini: WAV, MP3, FLAC, OGG, AAC, AIFF. OpenAI: WAV/MP3.
- Проверяются расширение, заголовок, обычный файл, размер и стабильность во время чтения.
- Нет автоматического хостинга, конвертации, извлечения кадров, обрезки диапазона или загрузки больших файлов через Files API.
- MIME-распознавание/превью может охватывать больше расширений, чем анализ; неподдерживаемые файлы требуют конвертации.
- У запроса есть таймаут и отмена. Не нужны дополнительные зависимости для обработки медиа.

## Проверки

Автономные тесты находятся в `scripts/media-attachments.test.mjs`, `scripts/media-catalog.test.mjs` и тестах инструментов/транспортов. Они не делают платных запросов и не проверяют реальную доступность провайдера. Для end-to-end проверки назначьте модель с API-ключом и прикрепите небольшой поддерживаемый файл.
