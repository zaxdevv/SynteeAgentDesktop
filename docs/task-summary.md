# Сводка задачи

Сводка в верхней правой части чата собирает план, опубликованные результаты, последовательность правок и проверки. Источник истины — main-процесс; данные сохраняются в SQLite отдельно от сообщений.

## Границы задач

Каждый самостоятельный запрос начинает задачу. Явные продолжения (`Продолжай`, `continue`, `Вот ошибка после…`) продолжают последнюю задачу, в том числе после остановки или ошибки. Это консервативная эвристика, не семантическое распознавание. Меню «Новая задача» принудительно разделяет следующий запрос. История ограничена 20 задачами на чат.

## Источники данных

- План: события `todo_update` инструмента `update_todo`.
- Результаты: только успешный `publish_result` с названием, типом (`file`, `image`, `url`) и абсолютным существующим файлом либо URL HTTP/HTTPS. Произвольный JSON из стороннего инструмента не считается публикацией.
- Изменения: успешные `edit_file`/`write_file` текущих запусков. Повторные правки одного пути объединены в последовательность патчей. Это **не суммарный git diff**; сохранённая последовательность ограничена по длине.
- Проверки: `get_diagnostics` и прямые известные команды проверки. Сбой запуска диагностики/неподдерживаемый стек — неизвестный результат, не зелёный проход. Shell pipelines не классифицируются: они могут скрывать exit code.
- Итог: детерминированное резюме завершённых пунктов плана, опубликованных результатов, проверок и числа изменённых файлов. Без дополнительного вызова модели и без пересказа первых строк ответа; оставшиеся пункты плана сохраняются отдельно.
- Участники (`TaskSummary.participants`): при каждом GET/live event объединяются актуальные данные AgentManager и delegated request DB. Сопоставление только по parent message ID из `task.messageIds`/явному source message ID; status/task/result не дублируются как отдельные snapshots. Summary максимум 6000 символов с удалением thinking. `done` обозначает окончание запуска, не успешную проверку.
- Делегированные поручения сохраняются по request ID (follow-ups — отдельные записи) с описанием и source message. `readAt` появляется при `read(result)` только если завершённое сообщение реально доступно; status/list не создают отметок прочтения.

## Persistence и приватность

Таблицы `task_summaries` и `task_summary_state` связаны с `chats` через `ON DELETE CASCADE`. При перезапуске незавершённые задачи переходят в `interrupted`. Инкогнито и эфемерные side-chat запуски не создают сохранённых сводок. Закрепления не являются долгосрочной памятью и не внедряются автоматически в контекст модели.

Старые чаты не обрабатываются задним числом: сводки собираются для новых запусков после обновления. Для изменений сохраняются ограниченные патчи, для проверок — ограниченный вывод. Файлы результатов не копируются: если удалить исходный файл, ссылка перестанет открываться.

## Проверки разработки

```powershell
node --experimental-strip-types --test tests/task-summary.test.mjs tests/task-summary-delegation.test.mjs
npm run build
```

Тесты проверяют запись первой задачи в SQLite, сохранение закреплений, восстановление после прерывания, каскадное удаление, эвристику продолжений и классификацию проверок. Полная типизация проекта может содержать несвязанные прежние ошибки; сборка и полная типизация — разные проверки.
